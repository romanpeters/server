# Codex CLI Developer Guide

This document describes how to work with this repository using the Codex CLI, an agentic coding assistant interface.

## Repository Layout

- `terraform/`       Terraform configurations for network, DNS, and VM/container provisioning.
- `ansible/`        Ansible playbooks and roles for configuring hosts (webserver, NixOS deploy).
- `hosts.csv`       CSV file defining hosts and their properties (IP, OS, etc.).
- `services.csv`    CSV file defining services for NGINX reverse-proxy and DNS.
- `tests/molecule/` Molecule scenarios for role testing using Docker.
- `Jenkinsfile`     CI pipeline: Terraform → NixOS deploy → Webserver config.
- `requirements.txt` Python dependencies for local development and testing.
- `ansible.cfg`     Configures Ansible to use the dynamic CSV inventory script.
- `README.md`       High-level project setup and usage instructions.

## Common Tasks

### Applying Terraform
    cd terraform
    terraform init
    terraform apply -auto-approve -var-file=vars.tfvars

### Ansible Playbooks
- Configure NGINX reverse-proxy on the webserver:
    ansible-playbook -i ansible/inventory/hosts_csv.py ansible/playbooks/webserver.yml
- Deploy NixOS configurations:
    ansible-playbook -i ansible/inventory/hosts_csv.py ansible/playbooks/nixos_deploy.yml

### Running Molecule Tests
    cd tests/molecule/webserver
    molecule test

### Linting & Formatting
Run code linters and formatters via pre-commit hooks:
    pre-commit run --all-files

## Codex CLI Commands

When interacting through Codex CLI (the agent interface), you can:
- `apply_patch`  Apply a unified diff patch to the workspace.
- `shell`        Execute shell commands and capture output.
- `git`          Inspect or modify git state (e.g., `git status`, `git commit`).
- Inspection Functions:
  - Read files: `shell(['bash','-lc','sed -n\'1,200p path/to/file\''])`
  - List directories: `shell(['bash','-lc','ls -R .'])`

__Note__: For detailed help, run:
```bash
codex --help
```

## Using Codex CLI

To open an interactive Codex session in this repository:
```bash
codex
```
Once started, you can issue natural language prompts and Codex will:
- Propose file changes via `apply_patch` calls
- Inspect the workspace using `shell` calls (e.g., run tests, list files)
- Manage Git state (e.g., `git status`, `git commit`)

Examples of Codex function calls:
```python
# List all files recursively
shell(["bash", "-lc", "ls -R ."])

# Apply a patch to update a file
apply_patch({"cmd": ["apply_patch", "*** Begin Patch\n*** Update File: path/to/file\n@@ ...\n+Hello\n*** End Patch"]})
```

To exit the session, send an ‘exit’ command or press `Ctrl-D`.

## Version Control

Commits are authored by the Codex agent. When possible, patches should be squashed or amended to keep history clean.
